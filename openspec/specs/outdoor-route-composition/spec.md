# outdoor-route-composition Specification

## Purpose

Defines a composite route built from an ordered recipe of other routes, with a materialized single-line GPX, so a workout can use a loop repeated several times as one ordinary route without changing the track model or any public read path.

## Requirements

### Requirement: A route can carry an ordered composition

The system SHALL store a composition as a sidecar of one materialized parent route, with ordered segments that name a child route, a role, a sort order, and a lap count. A plain route SHALL have no composition and SHALL keep its current behaviour. A route SHALL also carry an ingredient flag that hides it from standalone use.

#### Scenario: A plain route keeps its behaviour

- **WHEN** a route has no composition
- **THEN** it is created, edited, previewed, attached, and deleted exactly as before
- **AND** its ingredient flag is false by default

#### Scenario: A child route is recorded in order

- **WHEN** a composition stores two segments
- **THEN** each segment names its child route, role, sort order, and lap count
- **AND** the order is unique inside the composition

#### Scenario: A child route cannot be nested

- **WHEN** a route that already has a composition is offered as a segment
- **THEN** the system refuses the composition with a validation message
- **AND** no segment is stored

### Requirement: The parent geometry is materialized from full child points

The system SHALL rebuild the parent route's geometry as one synthetic GPX built from the children's full precision points in order, repeating a loop segment as many times as its lap count, and SHALL parse the generated bytes into the parent's metadata. The rebuild SHALL retire the previous generated file and SHALL leave the track model and every public read path unchanged.

#### Scenario: A two-lap run is materialized

- **WHEN** a composition holds one `MAIN` segment with a lap count of three
- **THEN** the parent's generated line contains the loop three times
- **AND** the parent's parsed distance, bounds, and point count come from the generated line
- **AND** the previous generated file is retired

#### Scenario: A repeated loop adds no duplicate closing point

- **WHEN** a loop's first and last point coincide within the loop-closure tolerance
- **THEN** the repeated line drops the duplicate closing point between laps
- **AND** the parent keeps its start point and gains no zero-length section at the seam

#### Scenario: Readers see an ordinary route

- **WHEN** a workout uses the parent route
- **THEN** its map, distance, and download come from the parent's generated file
- **AND** no track column or public payload changes

### Requirement: Composition input is validated and refused explicitly

The system SHALL refuse a composition that names another owner's route, a nested child, the parent itself, an empty segment list, a duplicate sort order, an unsupported role, a lap count below one, an unparseable child, or a gap between consecutive segments beyond the continuity tolerance. A refusal SHALL name the reason and SHALL store nothing.

#### Scenario: Gap between segments is refused

- **WHEN** the first point of the next segment lies farther from the previous segment's last point than the continuity tolerance
- **THEN** the system refuses the composition with a validation message that names the measured gap
- **AND** the parent geometry is unchanged

#### Scenario: A lap count must be positive

- **WHEN** a segment is offered with a lap count of zero or a negative number
- **THEN** the system refuses the composition with a validation message
- **AND** no segment is stored

#### Scenario: Only the main role is authorable

- **WHEN** a segment is offered with a start or end role
- **THEN** the system refuses the composition with a validation message until start and end segments ship
- **AND** no segment is stored

#### Scenario: A shared parent asks for confirmation

- **WHEN** the parent route is used by more than one track and the caller has not confirmed the shared change
- **THEN** the system refuses the composition with a shared-confirmation result that names the track count
- **AND** the parent geometry is unchanged

### Requirement: A child geometry edit rebuilds its parents

The system SHALL rebuild every parent composition that uses a route after that route's geometry changes. A failed rebuild SHALL leave the child change committed, SHALL mark the affected parent's composition as stale, and SHALL NOT report the rebuild as successful.

#### Scenario: Child edit updates the parent

- **WHEN** the owner changes the geometry of a route used as a child
- **THEN** every parent composition using it is rebuilt
- **AND** the parents' maps and distances reflect the new child shape

#### Scenario: Failed rebuild marks the parent stale

- **WHEN** a parent rebuild fails after the child geometry was saved
- **THEN** the child keeps its new geometry
- **AND** the parent's composition is marked stale
- **AND** the parent keeps serving its last good geometry until a rebuild succeeds

#### Scenario: Successful rebuild clears the marker

- **WHEN** a stale composition is rebuilt successfully
- **THEN** its stale marker is cleared
- **AND** the parent serves the regenerated geometry

### Requirement: Ingredients are protected from deletion and standalone attach

The system SHALL refuse deleting a route that any composition uses as a child, and SHALL refuse using an ingredient route as a workout's geometry.

#### Scenario: A child in use cannot be deleted

- **WHEN** the owner deletes a route that a composition uses as a child
- **THEN** the system refuses with an in-use result that names the number of compositions
- **AND** neither the route nor its file is removed

#### Scenario: An ingredient route cannot become a workout

- **WHEN** a workout creation or attach path receives a route marked as an ingredient
- **THEN** the system refuses with a validation message
- **AND** no track is created or changed

#### Scenario: Deleting a parent removes only the recipe

- **WHEN** the owner deletes a parent route with no linked tracks
- **THEN** its composition and segments are removed with it
- **AND** the child routes remain usable and unchanged
